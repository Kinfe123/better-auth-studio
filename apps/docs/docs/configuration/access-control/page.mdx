# Access Control

The project has role, email, or IP allowlist and blocklist access controls.
## What This Is
Access control defines who can open and operate the administrative surface. This page explains the relationship between roles, explicit email allowlists, IP rules, and the default behavior when no rule matches.
## Why It Matters
Access Control matters because it is part of how Better Auth Studio turns repository behavior into a usable developer or operator workflow. This page gives readers the mental model first, then uses implementation evidence as supporting context.
## Core Concepts
- roles
- allowlist
- blocklist
- admin access
- IP rules
## Typical Workflow
1. Decide whether access is controlled by role, email, IP, or a combination.
2. Configure allow and block rules before exposing the route in production.
3. Test denied and allowed users so operators understand the security boundary.
## Detailed Configuration Model
Access Control controls behavior rather than UI copy. The important questions are what decision this configuration helps a developer make, what happens when it is absent, and what runtime behavior changes when it is enabled. ### Configuration Options
| Option                    | Required | Description                                                                                                                                   |
| ------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth`                    | Yes      | Your Better Auth instance                                                                                                                     |
| `basePath`                | Yes      | URL path where studio is mounted                                                                                                              |
| `access.allowEmails`      | No       | Array of admin email addresses                                                                                                                |
| `access.roles`            | No       | Array of allowed user roles                                                                                                                   |
| `access.allowIpAddresses` | No       | IP allowlist for Studio requests. Supports exact IPs and wildcard patterns (example: `192.168.*`)                                             |
| `access.blockIpAddresses` | No       | IP blocklist for Studio requests. Supports exact IPs and wildcard patterns                                                                    |
| `ipAddress`               | No       | IP geolocation for Events/Sessions: `provider` ("ipinfo" \| "ipapi"), `apiToken`, `baseUrl`, optional `endpoint` (ipinfo: "lite" \| "lookup") |
| `lastSeenAt`              | No       | Enable last-seen tracking: `{ enabled: true, columnName?: string }`                                                                           |
| `metadata`                | No       | Custom branding (title, theme)                                                                                                                |

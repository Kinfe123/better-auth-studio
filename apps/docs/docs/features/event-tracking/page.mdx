# Event Tracking

The project includes event ingestion, audit, analytics, activity, or last-seen tracking.
## What This Is
This capability turns runtime activity into a timeline that administrators can inspect. It is especially useful for auth products because sign-ins, session creation, account updates, and organization events often need auditability and context.
## Why It Matters
Event Tracking matters because it is part of how Better Auth Studio turns repository behavior into a usable developer or operator workflow. This page gives readers the mental model first, then uses implementation evidence as supporting context.
## Core Concepts
- events
- audit trail
- activity feed
- last seen
- event providers
## Typical Workflow
1. Capture events from the host application or configured provider.
2. Normalize events into a consistent shape for display and filtering.
3. Use the event timeline to explain user, session, organization, or system activity.

### 👥 User Management
- **View all users** - Paginated list with search and filtering
- **Create users** - Add new users with email/password
- **Edit users** - Update user information, email verification status
- **Delete users** - Remove users from the system
- **Bulk operations** - Seed multiple test users
- **User details** - View user profiles, and accounts
- **Last seen** - When events are enabled, the studio injects an optional `lastSeenAt` field on the user model and updates it on each sign-in or session creation. Run your database migration (e.g. `prisma migrate dev` or Drizzle push) to add the `lastSeenAt` column to the user table.

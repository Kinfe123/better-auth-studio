## Detailed Configuration Model
Database controls behavior rather than UI copy. The important questions are what decision this configuration helps a developer make, what happens when it is absent, and what runtime behavior changes when it is enabled. This page keeps the mental model ahead of the raw files that mention the setting.

For Better Auth Studio, configuration usually answers practical questions: which services the command or runtime connects to, which secrets or URLs must be present, which defaults are safe for local use, and which values change scale, safety, or output. Each setting is documented in relation to one of those questions.

## Decision Points
- Is the setting required for every installation, or only for a specific framework, adapter, or deployment mode?
- Does the setting affect credentials, persistence, batching, integrations, output, or developer convenience?
- What does a developer verify after changing it?

## Repository Notes
These notes come from the repository README so the page stays grounded in existing project language.

### Supported Database Adapters
Better Auth Studio automatically detects and works with:

- **Prisma** (`prismaAdapter`)
- **Drizzle** (`drizzleAdapter`)
- **SQLite** (`new Database()` from better-sqlite3)
- **PostgreSQL** (via Prisma or Drizzle)
- **MySQL** (via Prisma or Drizzle)

# Database Adapters

Database adapters connect the product to the persistence layer used by the host application.
## What This Is
Database adapter docs explain how the product connects to the persistence layer used by the host application. They identify supported adapters, the expected provider names, and what needs to be migrated before the runtime can read or write records safely.
## When To Use This
- Use this when database adapters changes how Better Auth Studio runs, connects, or behaves.
- Use it to decide which values are required, optional, or only needed for a specific workflow.
- Verify configuration changes with the smallest command or integration path that exercises them.
## Core Concepts
- Prisma
- Drizzle
- SQLite
- Postgres
- MySQL
- schema detection
## Typical Workflow
1. Identify which adapter the host application already uses.
2. Confirm that the product can load the adapter and database connection from the host configuration.
3. Run migrations or schema pushes before using features that require additional columns.

### Supported Database Adapters
- Prisma (prismaAdapter)
- Drizzle (drizzleAdapter)
- SQLite (new Database() from better sqlite3)
- PostgreSQL (via Prisma or Drizzle)
- MySQL (via Prisma or Drizzle)
## How To Verify Changes

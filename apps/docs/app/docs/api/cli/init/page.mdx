# Init Command

The CLI exposes an init command for creating product configuration.
## Command Purpose
The init command creates or updates the configuration files needed to embed the product. This page explains what files are written, how existing files are handled, and what a developer verifies before committing the result.
## How to Run It
Run `pnpm start` from the project root after dependencies and required environment values are ready.
Install dependencies first with `pnpm install`.
## What the Command Depends On
The command reads environment-backed configuration. Set these values before using large runs or automation.
- `CLICKHOUSE_HOST`
- `CLICKHOUSE_PASSWORD`
- `CLICKHOUSE_USERNAME`
- `DISCORD_CLIENT_ID`
- `DISCORD_CLIENT_SECRET`
- `GITHUB_CLIENT_ID`
- `GITHUB_CLIENT_SECRET`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `BETTER_AUTH_SECRET`
- 25 more environment variables appear elsewhere in the project; document them on the page for the workflow that uses them.
## Flags and Options
Use flags to override defaults for a specific run. Prefer the default script first, then add flags when you need a different scale, concurrency level, target, or debug mode.
- `--api-dir <path>`: Custom app directory path for Next.js (e.g., "app" or "src/app"). The command will auto-detect "app" or "src/app" if not provided.
- `--watch`: Watch for changes in auth config file and reload server
- `--config <path>`: Path to the auth configuration file
- `--host <host>`: Host to run the studio on
- `--port <port>`: Port to run the studio on
- `--geo-db <path>`: Path to MaxMind GeoLite2 database file (.mmdb
- `--no-open`: Do not open browser automatically
## Useful Commands
- `dev` runs `tsx src/cli.ts` and starts the local development workflow.
- `start` runs `node dist/cli.js` and starts the runtime entrypoint after dependencies or build output are ready.
- `studio` runs `tsx src/cli.ts` and starts the runtime entrypoint after dependencies or build output are ready.
- `frontend:dev` runs `cd frontend && pnpm run dev` and starts the local development workflow.
- `frontend:preview` runs `cd frontend && pnpm run preview` and supports the project workflow.
- `build` runs `pnpm run clean && tsc && pnpm run frontend:build && pnpm run copy:public && pnpm run verify:public` and creates the production build or compiled package artifacts.

# Express Setup

The repository includes a Express adapter or example for self-hosted usage.
## What This Is
This setup page explains how to run the product inside a Express application. It covers the runtime dependency, the framework route or server hook, and the configuration the host app must provide.

⚠️ Beta Feature : Self hosting is currently in beta.  Please report any issues on GitHub.
## When To Use This
- Use this when you want to run Better Auth Studio inside your own application or infrastructure.
- Use it to separate what the host app owns from what the package provides.
- Review environment and deployment settings before exposing the runtime in production.
## Core Concepts
- Express
- self-hosting
- runtime dependency
- route mount
- host app config
## Typical Workflow
1. Install the package where the production server can import it.
2. Create the Express route, handler, or server integration.
3. Verify the product can read the same runtime, database, and access configuration as the host app.
## Runtime Shape
This page focuses on the Express runtime path provided by adapters, examples, or package exports.
Use `better-auth-studio/express` when wiring this runtime from the package export.
## Integration Story
For Express, the important idea is that the host application owns runtime state, database access, routing, and deployment. Better Auth Studio provides the handler or adapter that plugs into that host application. This page makes that boundary clear so developers know what the package supplies and what their app must still configure.
## Setup Checklist
1. Install dependencies with `pnpm install`.
2. Configure required environment variables before starting the runtime.
3. Run `pnpm start` or the framework-specific command from the host app.
4. Verify the mounted route, API handler, or container can reach the same runtime and database configuration as the host app.

# Self-Hosting Overview

Self-hosting explains how to run the product inside infrastructure you control.
## What This Is
Self-hosting explains how the package runs inside or next to a user's own application. It clarifies which pieces are required at runtime, how the host app mounts the product, and what infrastructure must be available in production.

⚠️ Beta Feature : Self hosting is currently in beta.  Please report any issues on GitHub.
## When To Use This
- Use this when you want to run Better Auth Studio inside your own application or infrastructure.
- Use it to separate what the host app owns from what the package provides.
- Review environment and deployment settings before exposing the runtime in production.
## Core Concepts
- runtime dependency
- host application
- deployment
- container
- production route
## Typical Workflow
1. Install the package as a runtime dependency when the host app serves it in production.
2. Mount the framework adapter or standalone server at the configured base path.
3. Verify that environment variables, database access, auth config, and allowed origins match production.
## Runtime Shape
This page covers the self-hosted runtime path described by deployment files, README sections, or configuration files.
## Integration Story
The important idea is that Better Auth Studio can run in a production environment controlled by the user. This page makes clear which files belong to the package and which runtime settings belong to the host application.
## Setup Checklist
1. Install dependencies with `pnpm install`.
2. Configure required environment variables before starting the runtime.
3. Run `pnpm start` or the framework-specific command from the host app.
4. Verify the mounted route, API handler, or container can reach the same runtime and database configuration as the host app.

# CLI Usage

CLI usage explains the commands and flags developers use to initialize, run, and debug the product.
## What This Is
CLI usage explains the command-line mental model: which commands exist, when to use each command, which flags affect runtime behavior, and how the CLI discovers project configuration.
## When To Use This
- Use this when you want to complete the cli usage workflow from start to finish.
- Use it as a task path first, then open reference pages only when you need exact flags or imports.
- Follow the verification step before increasing scale or automating the workflow.
## Core Concepts
- commands
- flags
- config discovery
- local development
- standalone server
## Typical Workflow
1. Install or run the CLI from the host project root.
2. Choose the command that matches the task, such as starting the studio or initializing config.
3. Pass flags for port, host, config path, watch mode, or other runtime behavior when defaults do not match the app.
## Before You Start
- Install dependencies with `pnpm install`.
- Confirm the main workflow with `pnpm start`.
- Review required configuration before running commands that create or mutate data.
## Run The Workflow
1. Install or run the CLI from the host project root.
2. Choose the command that matches the task, such as starting the studio or initializing config.
3. Pass flags for port, host, config path, watch mode, or other runtime behavior when defaults do not match the app.
## Useful Commands
- `start` runs `node dist/cli.js` and starts the runtime entrypoint after dependencies or build output are ready.
- `dev` runs `tsx src/cli.ts` and starts the local development workflow.
- `studio` runs `tsx src/cli.ts` and starts the runtime entrypoint after dependencies or build output are ready.
- `frontend:dev` runs `cd frontend && pnpm run dev` and starts the local development workflow.
- `frontend:preview` runs `cd frontend && pnpm run preview` and supports the project workflow.
- `build` runs `pnpm run clean && tsc && pnpm run frontend:build && pnpm run copy:public && pnpm run verify:public` and creates the production build or compiled package artifacts.
## Useful Options
- `--api-dir <path>`: Custom app directory path for Next.js (e.g., "app" or "src/app"). The command will auto-detect "app" or "src/app" if not provided.
- `--host <host>`: Host to run the studio on
- `--port <port>`: Port to run the studio on
- `--config <path>`: Path to the auth configuration file
- `--watch`: Watch for changes in auth config file and reload server
- `--geo-db <path>`: Path to MaxMind GeoLite2 database file (.mmdb
- `--no-open`: Do not open browser automatically

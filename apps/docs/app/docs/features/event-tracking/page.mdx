# Event Tracking

The project includes event ingestion, audit, analytics, activity, or last-seen tracking.
## What This Is
This capability turns runtime activity into a timeline that administrators can inspect. It is especially useful for auth products because sign-ins, session creation, account updates, and organization events often need auditability and context.
## When To Use This
- Use this when you want to understand what event tracking lets a user or operator accomplish.
- Use it before changing UI, routes, permissions, or data flows tied to the capability.
- Pair it with setup and configuration pages when the feature depends on runtime values.

## Typical Workflow
1. Capture events from the host application or configured provider.
2. Normalize events into a consistent shape for display and filtering.
3. Use the event timeline to explain user, session, organization, or system activity.

### Configuration Options
- `auth` (required) - Your Better Auth instance
- `basePath` (required) - URL path where studio is mounted
- `access.allowEmails` (optional) - Array of admin email addresses
- `access.roles` (optional) - Array of allowed user roles
- `access.allowIpAddresses` (optional) - IP allowlist for Studio requests. Supports exact IPs and wildcard patterns (example: 192.168. )
- `access.blockIpAddresses` (optional) - IP blocklist for Studio requests. Supports exact IPs and wildcard patterns
- 3 more settings are described in the README.
